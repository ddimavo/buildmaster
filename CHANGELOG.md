# История изменений

Формат: заголовок `## [версия]`. Раздел нужной версии автоматически попадает в описание релиза на GitHub.

## [Не выпущено]

_Сюда добавляются изменения до следующего релиза; номер версии назначается при выпуске._

### Предметы плагина, рецепты администратора и Nexo (база)
- **Свои предметы** (`items/*.yml`): материал, название, описание, `custom_model_data`/`item_model` или внешний вид из Nexo. Предмет несёт метку в данных предмета (`industryreborn:item`): подделать переименованием нельзя. Выдача: `/district item give`.
- **Единая ссылка на предмет** как в рецептах Nexo: `IRON_INGOT`, `ir:steel`, `nexo:steel_ingot`. Мост к Nexo работает через его API (`NexoItems`), необязателен и подключается по событию загрузки предметов Nexo; без Nexo всё работает.
- **Рецепты администратора** (`recipes/*.yml`): станок (печь, плавильная печь, коптильня, наковальня), время, от 1 до 4 входов (в т. ч. списком вариантов), результат - материал, предмет плагина или Nexo. Появляются в меню станка с названием предмета, сырьё принимают сундуки сырья и загрузка (предметы плагина и Nexo - только с настоящей меткой).
- Склад мастерской хранит предметы плагина и Nexo отдельно. Предмет Nexo, ещё не загруженный, ставит станок на паузу («предмет недоступен»), ничего не расходуя.
- Рецепты без `free: true` нужно **изучить**: закреплены за предприятием, сохраняются при продаже, аренде и изъятии (пока `/district recipe learn|forget` администратором; чертежи, заявки и магазин - следующие этапы).
- `/district item export-nexo`: заготовка предметов для Nexo и NexoHelper с `PersistentData`. Команды `/district item ...`, `/district recipe ...`; настройка `custom-items.enabled`.

### Чертежи
- **Чертёж** - одноразовый предмет, который открывает мастерской рецепт администратора: `/district blueprint use` (с чертежом в руке) или кнопка «Чертежи и рецепты» в меню «Производство». Расходуется всегда; рецепт навсегда закрепляется за предприятием (остаётся при продаже, аренде, изъятии). Изучают управляющий и работники.
- **Защита от дюпа:** у каждого чертежа серийный номер, использованные номера запоминаются.
- **Магазин чертежей администрации** (`/district blueprint shop|buy`): цена `blueprint_price` в файле рецепта, деньги в казну. Игроки чертежи не продают: в магазинах плагина они не принимаются, сделки ChestShop с чертежом отменяются (на настоящем ChestShop не проверялось).
- `/district blueprint give` - выдача администратором (например, как приз).
- **Хранилище администрации** (право `industryreborn.vault`, входит в `industryreborn.admin`): чертежи, которые нельзя продать через аукцион казны или удалить (решения по арестованным вещам, истёкший срок хранения), уходят туда; администратор забирает их и распоряжается как угодно, забранный чертёж снова рабочий. Меню и `/district blueprint vault [put]`.
- Рецепты: `blueprint_price` и `blueprint_item` (внешний вид чертежа - предмет плагина или Nexo); настройка `blueprints.material`.

### Классы номеров отелей
- У номера есть класс: **Эконом ★ / Стандарт ★★ / Комфорт ★★★ / Люкс ★★★★**, по умолчанию эконом (у существующих номеров тоже). Класс виден на голограмме над дверью, в меню «Номера отеля», в карточке номера и в `/district room list`.
- **Администратор** создаёт номер любого класса без проверки (`room auto|create|template ... [класс]`) и меняет класс сразу: `/district room class <номер> <класс>` или меню.
- **Управляющий отеля** подаёт **заявку** на смену класса (команда, ПКМ по номеру в меню номеров, кнопка «Класс номера»); администратор одобряет или отклоняет с причиной (причина идёт управляющему и в его журнал). Одна заявка на номер за раз; устаревшая (номер удалён, сменился управляющий) снимается сама.
- **Администратор может телепортироваться к двери номера**, ожидающего смены класса: Shift+ЛКМ по заявке в «Модерации» или `/district moderation tp <№>` (встаёт в коридоре перед дверью лицом к ней; нет двери - обычный телепорт к номеру).
- **Что даёт класс** (`hotel-classes` в config.yml, `enabled: false` отключает): границы цены за сутки (управляющему и при смене класса, администратору можно любую), максимальный срок аренды (3/7/14/14 суток), множитель электричества номера (×1.0/1.0/1.2/1.5). **Внимание:** все существующие номера - эконом, а у эконома срок аренды 3 суток; измените значения или назначьте классы.
- В меню номеров отеля: фильтр по классу, иконка кровати по классу, сводка «занято из» по классам. Новый вид заявки «Класс номера» в меню модерации.
- Статистика: число номеров, занятость и **доход по классам** в Plan (вкладка «Отели»), вебхуках и сводке; доход номера считается по его текущему классу.
- Смены класса и подгонка цены пишутся в журнал.

## [2.11.0]

### Витрина-голограмма стала таблицей
- **Иконка - название - цена - остаток** в колонках, строка на товар. Раньше предмет налезал на текст, а текст вращался к игроку; теперь доска стоит строго по направлению витрины и не «ползёт» при взгляде под углом.
- **Каждая ячейка - отдельная сущность** с фиксированной шириной колонки: длинное название или цена переносится внутри своей колонки и не заходит на соседние. Иконки - плоские значки, как в инвентаре.
- Сверху название предприятия и страница, подписи колонок «Товар / Цена / Остаток», внизу подсказка. Остаток цветом: зелёный много, оранжевый до 10, красный «Нет». Стрелки ◀ ▶ по краям доски.
- **Вторая доска с обратной стороны** (по умолчанию включена, `holo-shop.two-sided`); у отдельной витрины отключается: `/district holoshop back <номер> on|off|default`. Стрелки сзади листают в зеркальную сторону.
- Новые настройки `holo-shop`: `row-height` (высота строки), `text-scale` (размер текста), `two-sided`. Число строк на странице теперь 1-8, по умолчанию 5 (было 3 товара); `spacing` больше не используется.
- С FancyHolograms иконки создаются через него, но без значка-«GUI» (его API такого режима не даёт): предмет показывается объёмным.

- **Список участков:** фильтры в шапке, карточки с цветной точкой статуса и иконкой типа, ПКМ - быстрое продление.
- **Карточка участка** по группам: АРЕНДА, ПРЕДПРИЯТИЕ, ВИД И ДОСТУП, ОПАСНАЯ ЗОНА (для администратора - АДМИНИСТРАЦИЯ).

- На новом каркасе также: работники (вкладки в шапке), производство (группы РАЗВИТИЕ и СТАНКИ), станок (категория - одна кнопка, поиск и зачарование в шапке), права и права игрока, моя работа, решение по арестованным вещам; хранилище, журнал, уведомления, мои заказы, доска объявлений, счета, банк, казна, настройки банка, модерация, арестованные вещи, номера отеля, витрина, товары, прайс и услуги, электросеть и станции. ## [2.10.2]

### Исправлено
- **Plan: «Invalid card width: 18» осталась после 2.10.1.** Причина: Plan хранит результаты провайдеров в своей базе и сам их не удаляет. Старые таблицы остались в базе под именем «IndustryReborn»
  и вместе с показателями давали ту же ошибку, хотя в коде таблиц уже не было. Основное дополнение теперь просит Plan удалить старые результаты и провайдеры (`@InvalidateMethod` для
  `plotsByCategory`, `topRevenue`, `treasuryOperations`, `playerPlotsTable`); это выполняется при регистрации, достаточно перезапустить сервер.
  Раскладку Plan проверили на исходниках его фронтенда: ошибку дают только сочетания «показатели + широкая таблица» и «статистика + широкая таблица» без графиков.
- **`/district build <участок> <здание>` у администратора: «Строить можно только на свободном участке, который сейчас не обрабатывается».** Теперь администратор строит и на своём (купленном
  или арендованном) участке - бесплатно, исходный вид не меняется. Для остальных случаев сообщения разные: «Участок занят игроком X» и «Участок сейчас обрабатывается (идёт сброс здания / снимок или стройка)».

## [2.10.0]

### Здание остаётся на участке и аукцион участков
- **Здание можно оставить** при отказе, окончании аренды, выселении и изъятии. Управляющий выбирает «Сброс здания при отказе: нет»; администратор - `/district evict|seize <номер> [keep|reset] <причина>`
  (по умолчанию - `keep-building.on-evict` / `on-seize`) или кнопки «…, здание оставить» в меню участка. Оставленное здание становится новым исходным видом участка (`keep-building.rebaseline`)
  и помечается «с готовым зданием». Вещи уходят в хранилище, при изъятии - под арестом.
- **Аукцион участков** (`/district lot ...`, функция `plot-auction`): администрация выставляет свободный участок, игрок продаёт свой купленный. Старт, **шаг ставки**, срок, необязательный выкуп.
  Деньги ставки списываются сразу и возвращаются перебитому; ставка в последние минуты продлевает торги; победитель становится управляющим, деньги идут в казну (при продаже игроком - с комиссией).
  На время торгов участок не купить и не арендовать по фиксированной цене; лимиты участков действуют на торгах.
- **Голограмма лота** с последней ставкой и ставившим, шагом ставки, минимальной следующей ставкой, выкупом и оставшимся временем; клик ПКМ - ставка, Shift+ПКМ - выкуп (с подтверждением).
- HTML-страница «Аукционы участков» с кнопками ставок и историей торгов; журнал, чат и вебхук (`lot`) о торгах.

## [2.9.0]

### Платное строительство для игроков и HTML-меню со скриншотами
- **Строительство для всех игроков.** Владелец или арендатор своего пустого участка заказывает здание сам: `/district build menu [участок]` (или раздел «Строительство» на главной
  HTML-странице и кнопка «Заказать здание» у участка в «Моих участках»). Цена - **за каждый блок** здания (`auto-build.price-per-block`, множители по типам - `price-categories`,
  минимум - `min-price`), деньги идут в казну. Без подтверждения ничего не списывается; при сбое постройки деньги возвращаются. Участок на время стройки заблокирован,
  в журнале запись «Строительство здания». Участки игроков (регионы WorldGuard), административные здания (банк, электростанция) и номера отелей не заказываются.
  Здание должно подходить участку по типу (`match-category`), помещаться по размеру и стоять на пустом месте.
- **Цена блока регулируется автоматически**, как остальные цены: новая корректировка `build-price` (множитель к базе из config.yml) в `auto-balance`; шаг, пределы, журнал, чат и
  вебхуки - общие. Отключается `auto-balance.adjust.build-price: false`. В таблицу `IndustryReborn-Balance.xlsx` добавлены параметры (блоков в сутки, цена блока),
  строка поступлений в казну «Строительство зданий игроками» и рекомендация для `auto-build.price-per-block`.
- **HTML-меню «Строительство»:** карточки зданий с превью, размером, числом блоков и ценой, вкладки типов (у администратора), страницы, окно здания с двумя картинками
  (снаружи и в разрезе), кнопка «Построить за N». Превью рисуются на сервере на Java2D по шаблону здания (кэш `plugins/IndustryReborn/previews/`, перерисовываются при изменении
  файла) и кладутся рядом со страницами MC GUI (`industryreborn/img/`); работают и для своих сохранённых и импортированных зданий.
- Без MC GUI: тот же заказ списком в чате с кликабельными кнопками. Администратор строит бесплатно на свободных участках; `build reload`, `save` и `import` - только администратору.

## [2.8.0]

### Свои здания: сохранение и импорт
- `/district build save <имя> <тип> [название]` - записывает построенное в игре здание (область выделяется топором) в `plugins/IndustryReborn/buildings/<имя>.ir.json`.
  Размер до 64 по каждой оси; пустые верхние слои отбрасываются; содержимое сундуков, таблички и сущности не сохраняются.

  `/district build import list` показывает файлы. Старый `.schematic` не читается (сохраните заново как `.schem`).
- Палитра файла расширена (до ~550 разных блоков, символы не только ASCII); если блоков больше - понятный отказ.

## [2.7.0]

### Автоматическое строительство
- При создании участка на пустой площадке плагин **сам ставит здание** подходящего типа и размера, а уже потом снимает его исходный вид: `/district create <номер> <тип> <цена|-> <аренда|->`
  подбирает самое большое здание из подходящих; `... build [здание]` - явно (если не получилось, участок не создаётся); `... nobuild` - без здания.
- Здание ставится по центру участка на уровне земли (при необходимости с поворотом на 90°), объём очищается от травы и листвы, под зданием подсыпается основание. Блоки ставятся пачками
  (`auto-build.blocks-per-tick`), сервер не подвисает. Занятый участок (чужая постройка, вода) и слишком неровный (`max-slope`) отклоняются; для готового участка есть `force`.
- `/district build list|reload|<участок> <здание> [force]` - список зданий и постройка на уже созданном свободном участке (исходный вид пересохраняется).

    (сырьё и продукция возвращаются, стоимость установки - нет). Команды `/district factory ...`, меню «Производство и улучшения».
  - **Лимит накопления:** склад сырья и буфер продукции ограничены; когда буфер полон или сырья нет, линия простаивает и не копит время впрок.
  - Скорость зависит от числа станков; без электричества (в том числе при отключении от станции) линия стоит, время простоя не засчитывается;
    в режиме `USAGE` каждая партия платится как операция станка. Операции попадают в статистику станков.
- **Улучшения мастерской** (`/district factory upgrade`, `levels`): платные уровни (со счёта предприятия, деньги уходят в казну) повышают
  число линий, скорость линий **и выполнения заказов клиентов**, вместимость склада и буфера, очередь заказов. Уровни и эффекты - в `upgrades` в `config.yml`
  (незаданные значения наследуются от предыдущего уровня).
- **При освобождении мастерской** сырьё и продукция возвращаются управляющему (в хранилище, если он оффлайн), при изъятии за нарушение
  арестовываются; уровень и линии сбрасываются, новый управляющий начинает с нуля.

### Ограничения
- Линии работают отдельно от очереди заказов клиентов: они не делят станки между собой.
- Установка линии и улучшения не возвращаются при освобождении мастерской.

## [1.5.0]

### Новые функции
- **Услуги мастерских: заказы и эскроу.** Клиент заказывает услугу в мастерской, материалы и оплата хранятся в эскроу, мастерская
  выполняет заказ сама, пока в ней есть электричество, клиент забирает результат.
  - **Услуги:** переплавка (рецепты печи берутся из игры, время - из рецепта), ремонт повреждённых предметов и дополнительные
    рецепты администратора (`services.recipes` в `config.yml`: например, 9 самородков в слиток).
  - **Прайс.** Управляющий включает услуги и назначает цену за единицу работы в пределах максимума администратора (меню «Прайс услуг»
    или `/district service price|toggle`).
  - **Заказ.** Материалы берутся из руки (ЛКМ) или все такие же из инвентаря (Shift+ЛКМ), команда `/district service order <мастерская> <услуга> [all]`.
    Сначала оплата и материалы уходят в эскроу, цена фиксируется на момент заказа.
  - **Время.** Станки одного типа работают на очередь заказов по порядку; несколько станков работают параллельно (две печи - вдвое быстрее).
    Разные типы станков (печь и наковальня) обрабатывают свои заказы одновременно. Скорость регулируется `services.time-factor`.
  - **Без электричества** (в том числе при отключении от станции) новые заказы не принимаются, заказы в работе замораживаются
    (время простоя не засчитывается), а готовые заказы можно забрать всегда. В режиме тарифа `USAGE` каждая единица работы платится как операция станка.
  - **Выдача.** Результат отдаётся клиенту (излишек - в хранилище), оплата поступает на **счёт мастерской**.
    Не забранный за `services.ready-expire-days` сут. заказ уходит в хранилище клиента, а оплата - мастерской.
  - **Отмена.** Клиент отменяет заказ, пока он в очереди (деньги и материалы возвращаются). Администратор отменяет любой заказ с обязательной причиной.
  - **Закрытие мастерской** (отказ, окончание аренды, изъятие): невыполненные заказы возвращаются клиентам с материалами и деньгами,
    готовые отдаются результатом, а оплата за них поступает на счёт мастерской и возвращается управляющему (при изъятии - за вычетом штрафа).
  - Меню «Услуги мастерской», «Мои заказы», «Прайс услуг»; уведомления управляющему о новых заказах и клиенту о готовности.

### Ограничения
- Исполнение виртуальное: заказ обрабатывается самой мастерской по таймеру и не требует, чтобы игрок стоял у станка и не использует предметы в блоках станков.
- Услуги зачарования пока нет (есть переплавка, ремонт и рецепты вида «N предметов в M предметов»).

## [1.4.0]

### Новые функции
- **Новые административные здания: Банк и Электростанция** (`/district create <номер> bank - -`, `... power_plant - -`).
  Создаёт только администратор, купить и арендовать их нельзя, в списке свободных участков они не показываются.
- **Банк** (`/district bank`, меню «Банк»):
  - управляющие работают со своими счетами: пополнение, снятие, выписка;
  - банковские работники (право `industryreborn.bank`) видят казну и **все счета предприятий** с историей операций;
  - **комиссии** за пополнение и снятие, **штраф при изъятии**, **налог на доход от сдачи в аренду**, **недельный налог на имущество**
    по типам участков. Всё настраивается командами и в меню, хранится в `bank.yml`; при изменении условий все управляющие получают уведомление;
  - режим **«операции только в здании банка»** включается переключателем (по умолчанию операции работают из любого места);
  - долг по налогу на имущество: сначала списывается со счёта предприятия, затем с кошелька управляющего, иначе копится как долг
    и взыскивается позже или при освобождении участка; банк может списать долг с причиной.
- **Электросеть и электростанции** (`/district grid`, меню «Электросеть», право `industryreborn.grid`):
  - единица потребления **V**: станок потребляет свой коэффициент в V в сутки, цена электроэнергии - цена 1 V;
  - у каждой станции есть **мощность** (V в сутки), её задаёт администратор при создании и меняет в панели станции;
  - предприятие подключено **ровно к одной станции**; новая мастерская подключается автоматически к наименее загруженной;
  - при **перегрузке** станции тариф подключённых предприятий растёт понемногу (шаг и предел в `grid.*`) и так же снижается, когда нагрузка в норме;
  - **отключение предприятия** (и целого района) от электростанции с обязательной причиной: тариф не начисляется, станки не работают,
    игрок видит, что предприятие отключено и почему;
  - **районы** (`/district area`) и отчёты о потреблении по районам: нагрузка, потреблённые V и деньги за сутки и за 7 суток.
- Отдельные права `industryreborn.bank` и `industryreborn.grid` (оба входят в `industryreborn.admin`).
- Голограммы банка и электростанции (мощность, перегрузка), статус подключения на голограмме мастерской.

### Изменения
- Казна (`/district treasury`) теперь требует права `industryreborn.bank`, тарифы (`power admin`, `power calc`) - права `industryreborn.grid`.
- Штраф при изъятии теперь настраивается банком (`bank.seizure-penalty-percent`, раньше `electricity.seizure-penalty-percent`).
- Пока в мире нет ни одной электростанции, сеть не действует и мастерские работают как раньше.

### Известные ограничения
- Налог на доход от сдачи в аренду уже настраивается и считается (`BankService.applyRentTax`), но пока нигде не применяется:
  в плагине ещё нет участков игроков и отелей, где арендодатель получает выручку.

## [1.3.0]

### Новые функции
- **Режим тарифа по факту использования (`USAGE`).** Каждая операция на станке (плавка, варка, ремонт на наковальне,
  зачарование) списывает со счёта предприятия `usage-base × коэффициент станка`. Не хватает денег - операция отменяется.
  Режим выбирает администратор: `/district power admin mode DAILY|USAGE`. В `USAGE` время деньги не списывает.
- **Переопределения тарифов командами администратора** (`/district power admin ...`): база, прогрессия, цена операции,
  коэффициенты станков, режим. Хранятся в отдельном `overrides.yml`, чтобы не стирались комментарии `config.yml`.
  Приоритет: скидка участка, затем команда администратора, затем `config.yml`. `reset` возвращает значение из конфига.
- **При изменении тарифа** расход по старому тарифу сначала закрывается, затем включается новый; владельцы мастерских
  получают уведомление и запись в журнал предупреждений.
- **Скидки участков** (`power admin discount <номер> <процент>`), действуют в обоих режимах и сбрасываются при смене управляющего.
- **Подарки и компенсации на счёт** (`power admin add <номер> <сумма> <причина>`): деньги берутся из казны, новые деньги не создаются.
- **Статистика использования станков** (`power admin stats [номер]`): операции и израсходованные деньги по типам станков
  и по участкам, самые загруженные мастерские. Хранится в `stats.yml`.
- `power admin info` показывает текущие значения и откуда они взяты (конфиг или команда администратора).
- Голограмма и меню участка показывают способ оплаты электричества в режиме `USAGE`.

## [1.2.0]

### Новые функции
- **Система прав на участке:** «Строительство», «Контейнеры», «Станки» выдаются игрокам по отдельности
  (меню «Права», `/district perm <игрок> <право> on|off`). `/district trust` по-прежнему выдаёт все три права.
- **Публичный режим:** управляющий может открыть для всех посетителей контейнеры и/или станки.
  Администратор разрешает или запрещает это для каждого типа участка (`public-permissions`).
- **Станки и лимиты по типам зданий** (`station-limits`): в магазине можно по одному верстаку, печи и наковальне,
  прочие станки запрещены с подсказкой купить мастерскую; ресторан - до 3 печей; склад - только верстак и контейнеры;
  дом и мастерская без ограничений.
- **Электричество мастерских.** Тариф в сутки = база × Σ коэффициент × (1 + прогрессия × k) по станкам.
  Без электричества печи, варочные стойки, наковальни и столы зачарований не работают; строить и торговать можно.
  Вне мастерских станки обычные. Время считается по работе сервера: простой не оплачивается.
- **Денежный счёт предприятия** у каждого участка (`/district account deposit|withdraw`), пополнить может любой игрок.
  Остаток возвращается управляющему при отказе и окончании аренды; при изъятии за нарушение удерживается 10% в казну.
- **Журнал предупреждений** (`/district warnings`, кнопка в меню): аренда заканчивается, электричество на исходе (за 24 и 6 часов)
  и закончилось, отказ в установке станка. Строка «Электричество» и «Обесточено» на голограмме мастерской.
- **Калькулятор тарифа** для администратора: `/district power calc smelter:2 anvil:1`.

### Изменения
- Список «доверенных» заменён правами; старые данные (`trusted`) автоматически получают все три права.
- Станки нельзя ставить и заменять через меню «Изменить здание».

## [1.1.0]

### Новые функции
- **Административные участки с управляющими.** Администратор создаёт участок (`/district create <номер> <тип> <цена|-> <аренда|->`),
  игрок покупает или арендует его и становится *управляющим*; главным владельцем остаётся администрация.
- **Типы участков:** дом, магазин, мастерская, ресторан, склад. Общий лимит владения и лимит по каждому типу в `config.yml`.
- **Аренда до 14 суток.** Цена задаётся за сутки, плагин умножает её на срок. Продлевать можно только так, чтобы остаток
  не превысил 14 суток (прошло 2 суток из 14 - продлить можно на 2).
- **Отсрочка платежа 3 суток.** Не хватило денег на автопродление - участок замораживается (строить нельзя, торговля табличками работает),
  затем отбирается. Игрок получает уведомления.
- **Хранилище игрока** (`/district storage`): сюда попадают все вещи, возвращённые с участков. Вещи хранятся 60 суток.
- **Возврат вещей каждому владельцу.** Плагин ведёт книгу учёта: кто какой блок поставил. Печь вернётся тому, кто её поставил,
  сундук - тому, кто поставил сундук, вместе с содержимым.
- **Антидюп:** исходные блоки здания при поломке не дают предметов (они всё равно восстановятся при сбросе).
- **Сброс здания по структурам Minecraft:** сохраняются данные блоков - тексты табличек, баннеры, головы, горшки и т.д.
- **Сброс по решению владельца** (`/district autoreset`) и по решению администратора в любой момент (`/district reset`).
- **Решения администратора с обязательной причиной:** выселение, изъятие, сброс, арест вещей. Все записываются в журнал,
  игрок видит причину сразу и позже в `/district journal`.
- **Изъятие участка** (`/district seize`) арестовывает вещи нарушителя; администратор решает их судьбу (`/district arrest ...`).
- **Голограммы участков** на `TextDisplay`: название, тип, управляющий, цены (если свободен), описание.
- **Модерация:** название и описание участка публикуются только после одобрения; отдельное меню для администратора,
  отклонение с причиной, телепорт к участку из списка заявок.
- **Казна:** отдельный счёт, на который уходят оплата аренды и покупки (`/district treasury`).
- **Меню:** фильтр по типу, сортировка по номеру, цене, аренде и размеру, поиск, журнал, хранилище, настройки участка.
- **CI:** сборка и тесты на каждый push, публикация jar в GitHub Releases по тегу `v*`.

### Изменения
- Команда создания участка теперь требует тип: `/district create <номер> <тип> <цена|-> <аренда|->`.
- `max-plots-per-player` заменён на `limits.total` и `limits.categories.*`.
- `max-rent-days` по умолчанию 14.
- Снимки зданий хранятся как структуры по чанкам (`snapshots/<номер>/`) вместо одного файла блоков.

### Исправления
- Сброс здания больше не теряет данные блоков (таблички, баннеры, головы).
- Ошибка загрузки чанка во время сброса больше не оставляет участок навсегда заблокированным.
