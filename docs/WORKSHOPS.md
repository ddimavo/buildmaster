План этапов W0-W4. Принятые решения помечены ✔, допущения, которые нужно подтвердить, - ⚠.

## 2. Что считается станком

| Тип | Блоки | Базовый коэффициент |
|---|---|---|
| `smelter` | печь, плавильная печь, коптильня | 1.0 |
| `anvil` | наковальня (обычная, повреждённая, сильно повреждённая) | 1.5 |
| `alchemy` | варочная стойка | 2.5 |
| `enchanting` | стол зачарований | 4.0 |

Верстак считается станком только для лимитов магазина (не платный). Значения коэффициентов - в `config.yml`,
переопределения администратора - в отдельном `overrides.yml` (чтобы Bukkit не стирал комментарии конфига).

### Лимиты станков по типам участка

Настраиваются в `config.yml`: `-1` без лимита, `0` запрещено, `N` не больше N на участок.

| Тип участка | Верстак | Печь (любая из 3) | Наковальня | Прочие станки |
|---|---|---|---|---|
| Дом | -1 | -1 | -1 | -1 (бесплатно) |
| Магазин | 1 | 1 | 1 | 0 |
| Мастерская | -1 | -1 | -1 | -1 (платно) |
| Ресторан ⚠ | 1 | 3 | 0 | 0 |
| Склад ⚠ | 0 | 0 | 0 | 0 |

При запрете игрок видит: «В здании типа "Магазин" такой станок ставить нельзя. Для станков нужна мастерская»,
и кнопку/подсказку со списком свободных мастерских.

## 3. Тариф

```
тариф_в_сутки = база × Σ по типам [ коэффициент(тип) × Σ по станкам этого типа (1 + прогрессия × k) ] × (1 − скидка)
                                                               k = 0, 1, 2, ... (номер такого же станка)
```

* Нет станков - тариф 0.
* Приоритет значений: скидка мастерской, затем переопределение админа, затем `config.yml`.
* Пример: база 100, прогрессия 0.1, две плавильни и одна наковальня: `100 × (1.0 + 1.1 + 1.5) = 360` в сутки.

### Режимы (выбирает администратор: `electricity.mode`)

* `DAILY` - суточный тариф списывается непрерывно (ленивый расчёт).
* `USAGE` - плата за каждую операцию: плавка, варка, ремонт на наковальне, зачарование.
  Цена операции = `usage-base × коэффициент(тип)`. При нехватке средств операция отменяется. Прогрессия в этом режиме не применяется ⚠.

## 4. Счёт

Поля мастерской: `power_balance`, `power_rate`, `power_updated_at` (в биллинговых секундах).

* Баланс на момент `t`: `баланс − тариф × (t − power_updated_at) / 86400`. Тиков нет.
* При смене тарифа (станок поставлен/снят, изменён коэффициент, скидка) сначала фиксируется списание по старому тарифу.
* Время «обесточивания»: `сейчас + баланс / тариф`.
* **Биллинговые часы:** раз в минуту к счётчику добавляется прошедшее время, но не больше порога (простой сервера не считается). Значение сохраняется.
* Пополнить счёт может любой игрок (`/district power deposit <сумма> [номер]`); деньги идут в казну, баланс принадлежит текущему управляющему.
* Сменился управляющий (аренда закончилась, участок отобран): остаток возвращается управляющему; при изъятии удерживается 10% в казну ⚠ (считаем от остатка на счёте).

## 5. Что происходит при нуле

* Станки мастерской не работают: отменяются `FurnaceBurnEvent`, `BrewEvent`/`BrewingStandFuelEvent`, результат наковальни, `PrepareItemEnchantEvent`.
* Игрок получает сообщение; на голограмме строка «Обесточено».
* Строить, торговать, пользоваться дверями и табличками можно.
* Остальные последствия не вводим: аренда и отсрочка работают как раньше.

## 6. Система прав

Права выдаёт управляющий (меню «Права» и команда `/district perm <игрок> <право> on|off`):

| Право | Что даёт |
|---|---|
| `BUILD` | ставить и ломать блоки (сейчас это «помощник») |
| `CONTAINERS` | открывать сундуки, бочки, шалкеры и т.п. |
| `STATIONS` | пользоваться станками |

* `trust` выдаёт все три права (как сейчас).
* Публичные права ⚠: управляющий может открыть `STATIONS` и/или `CONTAINERS` для **всех** посетителей.
  Администратор может запретить публичный режим для отдельных типов участков.
* Блоки, поставленные помощником, по-прежнему возвращаются именно ему.

## 7. Журнал предупреждений

Отдельный от журнала решений администрации: личные уведомления игрока.

* Записи: аренда заканчивается, платёж просрочен (заморозка), электричество на исходе (24 ч и 6 ч), станки отключены,
  отказ в установке станка (тип здания не подходит), заявка отклонена.
* Хранится в файле; в меню - кнопка «Журнал предупреждений» (в главном меню и в карточке участка), счётчик непрочитанных.
* При входе в игру - сообщение о числе непрочитанных.

## 8. Команды

```
/district power                          тариф, баланс, на сколько хватит
/district power deposit <сумма> [номер]  пополнить счёт
/district power calc [станки]            калькулятор тарифа (админ): smelter:2 anvil:1
/district power admin base <число>
/district power admin coef set|reset|list <тип> [число]
/district power admin discount <номер> <%>
/district power admin add <номер> <сумма>   подарок/компенсация
/district power admin mode DAILY|USAGE
/district perm <игрок> <право> on|off [номер]
/district warnings                       журнал предупреждений
```

При изменении коэффициента сначала закрывается расчёт по старому тарифу, затем включается новый; владельцы уведомляются.

## 9. Конфиг (набросок)

```yaml
electricity:
  mode: DAILY            # DAILY | USAGE
  base-rate-per-day: 100.0
  usage-base: 1.0
  progression-per-extra-same-type: 0.10
  stations:
    smelter: 1.0
    anvil: 1.5
    alchemy: 2.5
    enchanting: 4.0
  warn-before-hours: [24, 6]
  seizure-penalty-percent: 10
  max-clock-step-seconds: 120
station-limits:          # -1 без лимита, 0 запрещено
  house:    {crafting: -1, furnace: -1, anvil: -1, other: -1}
  shop:     {crafting: 1,  furnace: 1,  anvil: 1,  other: 0}
  workshop: {crafting: -1, furnace: -1, anvil: -1, other: -1}
```

## 10. Этапы

| Этап | Содержание | Тесты |
|---|---|---|
| **W0** | Система прав (`BUILD`, `CONTAINERS`, `STATIONS`, публичный режим), меню «Права», команда `perm`; миграция `trusted` | права в `ProtectionListener`, миграция |
| **W1** | Реестр станков и лимиты по типам участка, запрет в магазине с подсказкой; электричество `DAILY`: формула, счёт, биллинговые часы, пополнение, отключение станков, голограмма, предупреждения и журнал предупреждений (меню), `power calc`, возврат остатка и штраф при изъятии | формула тарифа, ленивый счёт, часы, лимиты, отключение станков, возврат/штраф |
| **W2** | Режим `USAGE`, переопределения админа (`overrides.yml`), скидки, подарки, статистика использования станков | режим USAGE, приоритеты значений |
| **W3** | Услуги: приём заказов, эскроу, заморозка при отключении, выдача готовых заказов | заказы, эскроу |
| **W4** | Генераторы (переработка сырья, а не создание из ничего), улучшения | производство, лимит накопления |

## 11. Допущения, требующие подтверждения ⚠

1. Штраф 10% при изъятии считается от остатка на электрическом счёте (выручка пока не отслеживается: учёт через ChestShop - позже).
2. Лимиты станков для ресторана и склада (таблица в разделе 2 - предложение).
3. «Одна печь» в магазине - любая из трёх (печь, плавильная печь, коптильня).
4. Вне мастерских станки работают как обычные ванильные блоки: печь печёт, наковальня чинит, но без электричества и особых свойств.
5. Публичный режим прав и право `STATIONS`/`CONTAINERS` для посетителей - как в разделе 6.
6. Режим `USAGE` без прогрессии.
